# PDF 提取兜底链的接受判据：从"读到行"改成"解出指标"

2026-10-23。改的是 `PdfLineExtractor` + `BankReportParser` 之间那层"哪条提取路子算成了"的判断。

起因：新华保险 2024 年报 291 页，PdfPig 只读出 4 页 64 行——但**非空**，于是兜底链认定
"这条路成了"，poppler 永远轮不到。换 poppler 跑，核心/综合偿付能力当场就解析出来了。

---

## 一、机制

`PdfPigLineSource` 是**逐页 try/catch** 的（2026-09 为了治"一页字体坏掉整份报废"而改成这样）：

```csharp
for (int pageNo = 1; pageNo <= doc.NumberOfPages; pageNo++)
{
    try { page = doc.GetPage(pageNo); pageText = page.Text; }
    catch { continue; }          // 这一页读不了，换下一页
    ...
}
```

坏页跳过是对的，但当**绝大多数页**都因为缺 CJK CMap 而抛时，返回的就是一份残缺结果。
而 `PdfLineExtractor` 的接受判据是：

```csharp
if (lines is { Count: > 0 }) { usedSource = s.Name; return lines; }
```

**"行数 > 0" 就算成功。** 一份 291 页的报告只读出 4 页，和读全了，在这条判据下没有区别。

## 二、全库影响面

`publish/data/reports` 下共 **456 份** PDF。两轮实测：

**第一轮**，统计 PdfPig 能读出非空文本的页数占比——只用来说明机制，**不是影响面**：

| 覆盖率 | 份数 |
|---|---|
| ≥ 0.9 | 436 |
| 0 页 / 打不开 | 14（PdfPig 返回空行，兜底正常生效，poppler 接手） |
| 0.014 ~ 0.77 | 6 |

**第二轮**，456 份各用 PdfPig 和 poppler 跑一遍，对结果不同的 22 份再按**产品口径**
（带 PageFilter、按 kind 选标签集）逐指标对账。真正的影响面是这个：

| 报告 | 现状 | 只用 poppler | poppler 独有的指标 |
|---|---|---|---|
| 601528 瑞丰银行 2025-06-30 | 3 | 14 | core_tier1_car tier1_car cost_income_ratio nim net_interest_spread liquidity_ratio lcr 和四个迁徙率 |
| 601009 南京银行 2024-12-31 | 12 | 15 | liquidity_ratio net_interest_spread top1_loan_ratio |
| 601009 南京银行 2025-12-31 | 12 | 15 | 同上 |
| 002839 张家港行 2025-06-30 | 10 | 13 | core_tier1_car tier1_car total_car |
| 002839 张家港行 2026-06-30 | 10 | 13 | 同上 |
| 601336 新华保险 2024-12-31 | 0 | 2 | core_solvency comprehensive_solvency |

**9 份报告、29 个指标**现在拿不到，而换一条提取路子就能拿到。
受害形态是**少**不是错——这些 key 现状根本没有值，而不是存了错值。

反方向也有，**4 份 PdfPig 比 poppler 强**（见下节），所以这不是"换条路就行"的事。

## 三、三个约束（都有实测）

**① 不能改成 poppler 优先。** PdfPig 按坐标聚类还原表格行，在不少版式上比 pdftotext -layout 强：

```
002948 青岛银行 2026-06-30    PdfPig 15 → poppler 12   PdfPig 独有 core_tier1_car tier1_car total_car
601963 重庆银行 2025-12-31    PdfPig 11 → poppler  8   PdfPig 独有 core_tier1_car tier1_car total_car
601818 光大银行 2024-12-31    PdfPig 16 → poppler 15   PdfPig 独有 provision_coverage
601077 渝农商行 2024-12-31    PdfPig 10 → poppler  9   PdfPig 独有 liquidity_ratio
```

**② 页覆盖率不能当判据。** 瑞丰 0.714 出事、重庆银行 0.376 没事；更要命的是
002839、601009、002736 这几份覆盖率都 **≥ 0.9**，照样各缺 1~3 项。
指标表落在哪几页是随机的，"读到百分之几的页"跟"有没有读到要的东西"不相关。

**③ 指标数阈值短路也会漏。** 这条是本次体检才问出来的，否定了一个看起来很自然的省时方案：

```
002839  PdfPig 已解出 10 项，poppler 还多 3 项
601009  PdfPig 已解出 12 项，poppler 还多 3 项
601963 2026-06-30  两条路都是 8 项，但 loan_provision_ratio 的值不一样
```

银行正常能解出 8~21 项，10 项、12 项看着都很健康——**任何挡得住"白跑一趟"的阈值，
都挡不住这几份的缺口**。要么不设阈值，要么注定漏。

## 四、判据：直接问"解出了几个指标"

兜底链要判的本来就不是"读到字了吗"，而是"这条路够不够用"，而够不够用的唯一标准是
**解析出多少指标**——跟 `Parse` 末尾那道 `minMetrics` 整份质量门槛是同一个尺度，
只是用在不同的决策上：

| 判断 | 现在 | 改后 |
|---|---|---|
| 这条 source 算不算成了 | 行数 > 0 | 两条都跑，解出指标多的赢 |
| 这份报告整体算不算成了 | 指标数 ≥ minMetrics（银行券商 3、保险 1） | 不变 |

## 五、方案：两条都跑，取解出指标多的那条

1. `Parse` 向组合器要**全部**可用 source 的行，而不是"第一个非空的"。
2. 对每条的行各跑一遍 `ScanAll`。
3. 取指标数最多的那条的结果。**平手时保持 source 顺序**（PdfPig 在前），即维持今天的行为。
4. OCR 兜底接在选中的那条后面，逻辑一个字不改。

**为什么不设阈值**：见上节③，10~12 项时仍有缺口，阈值挡不住。

**为什么不取并集**：产品口径对账 13 份差异报告，**没有一份出现"两条路互有独有"**——
独有项的方向永远是单一的。既然并集换不来额外的指标，就没有理由承担它的代价：
并集会把两条路的值混进同一份结果（source_page 指向不同的提取路径），人工核对时对不上账。

**成本**：456 份提取耗时实测 PdfPig 806 秒、poppler 611 秒（单线程累计）。
现状只跑 PdfPig，【重解析已有PDF】约 13 分钟；改后两条都跑，约 24 分钟。
这个任务是手动/每月触发的，日常增量每天只有几份新报告，无感。

## 六、职责边界

`PdfLineExtractor` 不认识"指标"，这个取舍不能塞进它（它的类注释专门写了"组合器只排顺序，
不懂业务"，OCR 当初就是因为这条才没被放进去）。分工：

- **组合器**：多给一个"把每条可用 source 的结果都交出来"的入口，自己不做取舍；
  原来"第一个非空的赢"的 `Extract` 保留，别的调用方（`SubsidiaryParser`）继续用。
- **BankReportParser**：拿到候选，各跑一遍 `ScanAll`，按指标数挑一条。
  "几个算够""哪条更好"是业务知识，留在业务侧。

## 九、顺带查出来的另一件事：两条路的值不一致

有 3 份报告，两条路对**同一个指标**给出了不同的值——至少有一条是错的：

```
601878 浙商证券 2025-12-31    net_stable_funding  risk_coverage
601077 渝农商行 2024-12-31    cost_income_ratio  net_interest_spread  tier1_car
601963 重庆银行 2026-06-30    loan_provision_ratio
```

**6 个值已经逐条核过了**（2026-10-23），办法是把两条路在那一页上的原文行并排打出来：

| 报告 | 指标 | 谁对 | 错的那条错在哪 |
|---|---|---|---|
| 浙商证券 | net_stable_funding | **poppler 156.80** | PdfPig 把右栏注释串进了表格行：`净稳定资金率（%）（7）2020年 1 月 8 日，淳安县应急管理局向浙期实业颁发了《危险化学品经营许可证》（浙杭（淳）安经字156.80 [2020]13003366），154.75`，取不到数，最后拿了**流动性覆盖率**的 263.17 |
| 浙商证券 | risk_coverage | **poppler 325.87** | 同一处串行，拿了**净资本/净资产**的 78.24 |
| 渝农商行 | cost_income_ratio | **PdfPig 31.86** | poppler 那行只剩 `成本收入比 7`，把脚注号当成了值 |
| 渝农商行 | net_interest_spread | **PdfPig 1.51** | 同上，`净利差 5` |
| 渝农商行 | tier1_car | **PdfPig 14.93** | poppler 的 `一级资本充足率` 行断了、后面没有数 |
| 重庆银行 | loan_provision_ratio | **PdfPig 2.75** | poppler 取自正文一句话：`商业银行拨备覆盖率202.87%，贷款拨备率为3.08%` ——那是**全行业**平均，不是本行 |

两个旁证坐实了浙商那两项是串行：库里 `broker_lcr` 和 `net_stable_funding` 都是 263.17、
`netcap_to_netassets` 和 `risk_coverage` 都是 78.24——同一页上两个不同指标取到完全相同的值。

**本方案的选路恰好每一项都选中了对的那条**：浙商选 poppler（8 项 > 6 项）、渝农商行选
PdfPig（10 > 9）、重庆银行平手选 PdfPig。这不是巧合——串行和断行会同时让"解出的指标变少"
和"取到的值出错"，所以"解出得多"跟"解得对"是相关的。

库里现状：浙商那 2 项是错的，其余 4 项本来就对。**跑完重解析，这 2 个错值会自动纠正。**

## 十、再顺带：同页同值的指标对

上面那个旁证可以做成一条通用的错值信号——**同一份报告、同一页、两个不同指标取到完全相同的值**。
全库扫了一遍：68 对，去掉迁徙率之间的 24 对（它们常常真的都是 100），**还剩 44 对**。
里面真假都有：`core_tier1_car = tier1_car` 对没发过优先股/永续债的小银行是真相等；
但 `lcr = liquidity_ratio`（中信银行连续四期）、`netcap_to_liab = netcap_to_netassets`
（太平洋证券连续四期）分母都不一样，不可能相等。

这 44 对后来逐对核完了，结论另开了一份：**doc/metric-value-audit-findings.md**——
29 对是真相等、15 个是错值，其中 2 个（浙商证券那两项）被本方案顺带修掉了，
其余 13 个另有三类错因，跟提取路子的选择无关。
