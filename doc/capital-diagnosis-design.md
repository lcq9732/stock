# 资金面诊断（Capital Diagnosis）设计方案

> 状态：**已实现并实机验证通过**（2026-09-16）。方案 2026-09-15 定，同日按宁德时代原型实跑修正了数据边界与大宗算法。
> 起因：手工查库分析宁德时代 2026-08~09 回调，发现"把几张表横着串起来得出的结论"是现有界面完全没有的一层。

---

## 1. 这个功能要解决什么

现有的个股信息分两层：

| 层 | 承载 | 回答的问题 |
|---|---|---|
| 条件详情（DetailWindow 等 7 个） | K线 + 命中条件标注 | **这个方法为什么选中它** |
| 行情详情 + 其他数据（QuoteDetailWindow / StockDossierWindow） | 原始表分节 + 趋势图 | **某天的值是多少 / 这条序列什么走势** |

缺的是**第三层：结论**——把 Bar / NetInflowDetail / MarginDetail / BlockTrade / LhbSeat 横着串起来，回答"这只票现在的量能和资金处于什么状态"。

例（宁德时代，锚点 2026-08-05 ~ 09-15，**下列数字全部由原型脚本实跑本地库得出**，见第 10 节）：

- 相对强弱：本股 -21.65%，创业板指 -8.12%、同业中位 -5.02% → 超额 -13.5pct / -16.6pct
- 量能档位：区间日均 94.9 亿 / 换手 0.61%，前期等长段 138.6 亿 → **量能为前期的 69%**；3 个放量日全部是放量下跌
- 资金流：主力 -85.3 亿、超大单 -48.3 亿，同期小单 +83.4 亿（机构派发、散户承接）
- 杠杆背离：股价 403.80 → 316.36（-21.7%），融资余额 220.4 → 236.2 亿（**+7.2%**，峰值 242.4 亿）→ **反向**
- 单日异动：9/15 主力 -34.0 亿，区间最大单日流出，当日 -6.16% 收在最低附近
- 大宗性质：33 笔 / 19.9 亿，金额加权溢价率 **-0.05%**，平价对倒占金额 99.7% → **不是折价甩卖**
- 龙虎榜：本波 0 次，最近一次上榜远在 2020-07-07

其中"近 60 日"那一行是个反例，值得单独记住：本股 -19.70% 而创业板指 -23.60%，**超额 +3.9pct**——
拉长窗口后结论符号翻转。这说明单看主锚点会误导，固定 20/60 日对照列是必需的，不是装饰。

这些没有一条需要新抓数据，但没有一条是现在点几下界面能看到的。

**用户明确要求：不管涨跌都要给同样的诊断。** 涨的时候同样输出"主力净流入多少 / 量能配不配合 / 融资跟没跟上"，不是只在跌的时候报警。

## 2. 数据基础与边界（实测，2026-09-15）

这一节决定了功能的能力上限，先于算法确定。

| 表 | 时间覆盖 | 标的数 | 对本功能的约束 |
|---|---|---|---|
| `Bar` (day) | 长历史 | 全 | 无约束。注意 `volume` 单位：科创板是股、其余是手（见 project_bar_volume_unit_bug），跨板块比量必须先归一 |
| `NetInflowDetail`（五档分档） | **2026-03-16 起（实际）** | 5,563 | **只有约 6 个月**。全表 `MIN` 是 2025-11-14，但那天只有 1 只票——零星数据，不可当作可用起点（会虚报 4 个月）。判定须按「覆盖只数达到全量 80% 的第一天」，实测 2026-03-13 才 1,526 只、03-16 才 5,464 只 |
| `NetInflow`（仅主力净额一列） | 2010-03-01 起 | 5,566 | 长历史可用。要做长区间/回测只能用这一列 |
| `MarginDetail` | 2010-03-31 起 | 4,637 | **只覆盖两融标的**（当日 4,105 只）。非两融标的必须显式显示"非两融标的"，不能显示 0 |
| `BlockTrade` | 2016-01-04 起 | 14,418 | 够用。含同日多笔，主键带 daily_rank |
| `LhbSeat` / `Lhb` | 2016-01-04 起 | 6,335 | 够用。注意 `Lhb` 的股票代码列名是 `stock_code` 不是 `code` |
| `StockIndustry` | 快照 | 6,026 | **粒度粗**：class_name 20 个门类、major_name 85 个大类。中位 27 只/类，21 类不足 10 只 |
| 指数 `Bar` | 长历史 | 9 个 | sh000001/sz399001/sz399006/sh000300/sh000905/sh000688/sz399106/sz399102/bj899050。**代码带市场前缀** |

**四条硬约束，方案必须显式处理：**

1. **分档资金流只有 6 个月** → 起始日**按标的各自计算**（宁德首日 2026-03-16），并在每个区间显示实际覆盖比（如 `30/30日`），不满时告警。默认区间不得超出；长区间自动降级到 `NetInflow` 的主力净额单列（2010 年起）。**不得用全表 `MIN` 当起点**（见上表）。
2. **两融只覆盖部分标的** → 缺失显示"非两融标的"，与"余额为 0"区分。
3. **行业粒度粗** → 同业对照按 `major_name`（85 类）优先，样本 < 10 只时退回 `class_name`，再不足则**放弃同业对照、只留指数对照**。这跟 PE 行业分位的降级规则（project_industry_pe_percentile）是同一个模式，规则应复用同一段代码。
4. **当日数据不齐** → 实测 9/15 当晚：`NetInflowDetail` 已有 5,548 只，`Bar` 只有 4,427 只、指数一条没有。诊断必须按"各表各自的最新可用日"对齐，并在界面显示每项的截止日期，不能假定所有表都到同一天。相关：盘中抓的 K 线不是最终值（project_intraday_bar_confirmation）。

## 3. 区间锚点

不让用户手工选区间——手工选会让结论不可比，也没人愿意每次点。

**主锚点：近 60 个交易日内的最高收盘日**。理由：
- 自动适配"这波走了多久"，宁德自动锚到 8/5（403.80），不用人去找
- 60 日是既定的短线口径（project_shortterm_focus）
- 涨势中锚点就是最近几天，区间很短，自然退化成"近期"诊断——符合"不管涨跌"的要求

**固定对照：近 20 日、近 60 日两列**，跟主锚点区间并排显示。主锚点回答"这波以来"，固定列回答"最近一个月/一季度"，两者互为参照，避免锚点选得刁钻时结论失真。

## 4. 诊断维度

每个维度在界面上是一个**四段式**区块，缺一不可（2026-09-16 修：v1 样例只给了表格没给结论句，
看起来就是原始数据换排版，正是本功能要解决的毛病本身）：

```
维度 N/6 · 维度名  ⓘ        ← ⓘ = Tooltip，静态口径说明藏在这里，不占行
  ⚠ 本次异常（仅异常时出现，正常时零占位）
  结论：1–2 句中性判断（规则拼装，不是自由发挥）
  证据：区间对照表 + Top3 明细
```

**口径必须拆成两类**（2026-09-16 定）——原来混成一行常驻显示，用户反馈"熟悉后就不用看了"：

| 类别 | 内容 | 去处 |
|---|---|---|
| **静态口径** | 指标定义、分档标准、算法选择理由、已知陷阱（如 volume 的手/股、溢价率为何要加权） | **Tooltip**，悬停才显示 |
| **本次异常** | 同业样本不足已降级、非两融标的、分档覆盖不满、某表截止日落后于 K 线、**区间内有缺日** | **仍然常驻**，但只在异常时出现 |

**异常检测清单**（2026-09-16 补：原设计漏了第 3 条，是查证宁德两融滞后时发现的）：

1. **降级** — 同业样本 < 10 已退回门类，或已放弃同业对照
2. **不适用** — 非两融标的、无分档数据（早于该标的起始日）
3. **区间内缺日** ⚠ — 该表在区间内某些交易日整天没有数据。实测：`MarginDetail` 的
   2026-08-21 和 2026-09-02 **深市整个缺失**（只有沪市 1,998 / 2,000 只，正常 4,100 只），
   2025 年以来 413 个数据日里就这 2 天。宁德是创业板，这两天的两融值就是缺的——
   首末值不受影响，但 Top3 明细会漏。必须显式告警，不能让缺日静默通过
4. **截止日落后** — 但要区分两种：
   - **正常滞后**：交易所披露规律。`MarginDetail` 实测每个交易日都在**次日**入库
     （09-14 的数据 09-16 01:38 抓到），所以永远比 K 线晚一天，这是预期内的，
     措辞应为"按披露规律属正常滞后"，不能写得像故障
   - **真落后**：超出该表既有的滞后规律。判据是拿该表**历史滞后天数的众数**当基线，
     超出才告警——不能简单用"日期 < K线日期"判，那会天天误报

分开的理由：静态说明看两次就够了，但异常是每次不同的。全塞进 Tooltip 会出现
**"结论看着正常、其实数据是降级的"**——宁德当前就命中一条（两融截止 09-14，比 K 线晚 1 日，
变化率未含最新一天）。这类信息一旦藏起来，结论就不可信了。

**结论句由规则拼装**（按符号、比值、阈值套模板），不是每次现编——保证同一组数据永远得出同一句话，
可回归测试。措辞规范见第 5 节。

### 4.1 相对强弱
- 本股区间涨跌幅 vs 所属市场指数（创业板→sz399006，主板→sh000001，科创→sh000688，北交→bj899050；按 MarketClassifier 判，见 feedback_market_prefix_via_classifier）
- vs 同业中位数涨跌幅（降级规则见约束 3）
- 输出超额收益 pct

### 4.2 量能档位
- 区间日均成交额 / 换手率，对比"区间之前等长的一段"
- 输出比值，如"量能为前期的 63%"
- 标出区间内的放量日（额 > 区间均值 ×1.5）与其当日涨跌幅——放量上涨与放量下跌意义相反，必须带方向

### 4.3 资金流
- 主力 / 超大单 / 大单 / 中单 / 小单区间累计净额（亿元）
- 近 5 日主力净额与区间整体方向是否一致 → "近期已转向"/"延续"
- 区间内主力单日净流出/入 Top 3 及当日涨跌幅

### 4.4 杠杆与背离（这一项信息量最高）
- 融资余额区间变化率 vs 股价区间变化率 → **符号相反时明确标注"背离"**
- 融券余额变化率
- 区间内融资买入额 Top 3 日
- 背离的含义只陈述事实（"股价跌 X%、融资余额升 Y%，杠杆资金在逆势加仓"），**不下"要平仓了"这类预测**

### 4.5 大宗交易性质
- 区间笔数、总金额、**金额加权**折溢价率
- 分类按**金额占比**（不是笔数）：平价对倒（|溢价率| < 0.5%）/ 折价（< -2%）/ 溢价（> 2%）
- ⚠ 必须金额加权：宁德实测 33 笔简单平均 -1.13%、金额加权仅 -0.05%，两笔 288 万的小单（占总额 0.14%）把简单平均拉出了"轻微折价"的假象。占比显示不得进位，否则 99.7% + 0.3% 会显示成 100% + 0.3%
- 买卖方是否为"机构专用"

### 4.6 龙虎榜
- 区间内上榜次数、上榜原因、机构席位净买卖
- 无上榜则明确显示"未上榜"（信息本身有意义）

## 5. 措辞与阈值规范

1. **只陈述事实与对比，不下买卖结论**。跟 PE 行业分位一样：说"量能为前期的 63%"，不说"缩量见底"。
2. **阈值克制**。只对"明显偏离"给提示（量能 < 前期 70% 或 > 150%、资金流与价格反向、融资与价格反向），不设多档评分。理由：RisingLows 回测已经吃过阈值过拟合的亏（project_risinglows_backtest_findings），在没有前向验证之前不要发明新的分档。
3. **每项带数据截止日和口径注释**，沿用 `DossierSection.Note` 的做法——那套注释（"户数上升=筹码分散"之类）已经证明有效。
4. **不做评分/总分**。把五个维度压成一个分数会掩盖矛盾信号（比如主力流出但融资在加仓），而矛盾信号恰恰是最该被看见的。

## 6. 代码结构

- **算法放 `StockPlatform.Logic`**：输入是已读好的序列（Bar / 资金流 / 两融 / 大宗 / 龙虎榜），输出诊断条目集合。零 IO，符合 Logic 层边界（project_logic_layer_boundary）。这样回测、晨检、FactorLab 都能复用同一份逻辑，不只服务于一个窗口。
- **读取放 Data 层**：可直接扩展 `SqliteStockDossierReader`——它已经在读其中 3 张表，再加指数/同业两段查询即可。注意 MarginDetail / BlockTrade / LhbSeat 主键最左列都不是股票代码，按代码查是全表扫，必须在后台线程（现有"其他数据"按钮已经这么做了）。
- **展示层待定**（见下）。

## 7. 入口：并入【分析详情】窗口，重排为三列（2026-09-16 定）

早先列的四个候选（行情详情加面板 / 档案窗口加一节 / 7 个条件详情各嵌 / 共享控件）**全部作废**。
用户选了第五个：并进现有的【分析详情】窗口（`FinancialAnalysisWindow`，从表格"代码"列点开），
把它从两列重排成三列。

理由：财务、事件、资金面本来就是同一只票的三个侧面，"一看就有了，也可对比数据"——
这正是 2026-09-14 把观察项并进这个窗口时的原话，资金面诊断是同一个逻辑的延续。

### 7.1 目标布局

```
┌──────────────────────┬────────────────────┬──────────────┐
│ ① 事件 + 资金面诊断   │ ② 2026年中报        │ ③ 趋势图      │
│   1.05*  (min 520)   │   0.95*  (min 490) │   190 固定    │
├──────────────────────┼────────────────────┼──────────────┤
│ 事件（原「观察项」）  │ 需要留意的 N 项     │ 营收          │
│ ──────────────       │ ──────────────     │ 净利          │
│ 维度1 相对强弱 ⓘ      │ ① 盈利             │ 毛利率        │
│ 维度2 量能档位 ⓘ      │ ② 现金流           │ 负债率        │
│ 维度3 资金流 ⓘ        │ ③ 负债             │ ...           │
│ 维度4 杠杆背离 ⓘ      │ ④ 运营             │              │
│ 维度5 大宗 ⓘ          │ ⑤ 成长             │              │
│ 维度6 龙虎榜 ⓘ        │                    │              │
└──────────────────────┴────────────────────┴──────────────┘
         整列一个 ScrollViewer        各自独立滚动
```

窗口尺寸实测：屏幕 1920×1040（双屏），`TextFitter.SizeToScreen` 取 0.92 → 窗口 1766×956。
减 `Margin=12`×2 和两条 6px splitter → **1730px 可分**。

### 7.2 三列各自的约束

**① 资金面诊断**（min 520）
- 六个维度，**全部排开、不折叠**（2026-09-16 用户定：先全排，超出就滚动，看了实际效果再决定要不要折叠）
- **整列一个 ScrollViewer**。六个维度全展开按原型约 900px，加事件 420 = 1320，
  远超可用高度 ~860px，所以必然要滚——这是已知且接受的
- 最宽的证据表是维度 1（区间/本股/指数/同业/vs指数/vs同业 六列），约需 500px

**② 财报分析**（min 490）
- 内容不变：需要留意的 N 项 + 五节明细 + 每节结论
- **标题改为报告期**（如「2026年中报」），须从最新报告期**动态取**，不可写死——
  可能是中报/三季报/年报
- ⚠ 宽度硬下限来自那张七列表（`FinancialAnalysisWindow.xaml` 的 SectionList）：
  死宽 = 标记 22 + 项目名 150 + 数值 92 + 变化 130 = **394**，加说明列至少 80 → **490**
- ⚠ **银行股要 730**：银行体检表多「条目号」和「参考值」（MaxWidth 230）两列，
  非银行票这两列 Collapsed 收缩到 0。窄列下银行票会换行——留 GridSplitter 让用户手动拖开

**③ 事件 + 趋势图**（min 240）
- 2026-09-16 用户明确要 190px（现在是 1*，MinWidth 380，约为一半）
- ⚠ 已知代价：OxyPlot 在 190px 宽下，纵轴刻度与报告期标签（`2026Q2` 这类）会挤甚至重叠。
  用户选择先按 190 做、看实际效果。如果确实读不出来，退路是把报告期标签改成斜排、
  或只标首尾两期（不要先做，等看了效果）

### 7.3 连带要改的两处

**「观察项」→「事件」**——零风险。`StockWatchPanel.xaml` 的注释已写明「这里**只有事件叙述**」，
个人观点和触发记录 2026-09-14 已砍，`DataGrid` 列头本来就叫「事件」。标题叫"观察项"是历史遗留，
改一个 `Text` 即可，**不涉及** `AnalyzerPaths` 里那套观察项定义（items.json / hits-{yyyy}.json）。

**「总体判断」挪到窗口顶部通栏**——现在 `HeaderText` 是"股票名 + 总体判断"合并一行
（2026-08-27 用户要求合并）。第 2 列标题改成报告期后，总体判断无处安放。
它本来就是对整只票的判断、不专属财报那一列，提到三列之上通栏一行最合适。

### 7.4 实机验证后的调整（2026-09-16）

按方案做完后起 Debug 实例实跑，用户看了实际效果定了六处（前四处第一轮，后两处第二轮）：

1. **列宽改成手拖出来的值**。方案里按字数估算给的是 `1.05* / 0.95* / 190固定`，
   实机一看第②列财报明细太挤、第③列 190 窄到 OxyPlot 的刻度和报告期标签打架。
   用户手动拖成 **591 : 916 : 377**，定为默认（写成 `1.57* / 2.43* / 1.0*`，
   star 而非像素，换屏幕按比例缩放）。第③列 MinWidth 从 190 提到 240。
2. **总体判断挪到第②列标题旁**。它原本在通栏标题行，但通栏右边被「复制全文」占着、
   给不出横向空间，而第②列标题「2026年中报」右边空着一大片。
3. **「同比基准 / 阈值」也归入第②列**。它解释的是第②列的数据（同比那一列拿哪期做基准、
   ✓!✗ 的判定线在哪），留在通栏右上角紧挨着趋势图，会被误读成在说趋势图——用户指出的。
4. **趋势图的口径说明收进标题 Tooltip**。理由跟六个维度的口径一样：解释"为什么只取同月份
   报告期"，看两次就不用再看，而它在那一列要占掉四五行。
   ⚠ 但"报告期不足，画不出趋势"仍然写在标题上——那是**本次的实际状态**不是口径，
   同一条"静态口径进 Tooltip、本次状态常驻"的规矩（见第 4 节）。
5. **事件从第①列挪到第③列趋势图上面**。第①列六个维度全展开约 900px、本来就要滚，
   上面再顶一个 420 的事件区等于凭空多滚半屏；而第③列竖向空间富余。
   封顶从 420 收到 320——这一列比原来窄（377 vs 1*），同样文本换行更多更占高度，
   而下面五张趋势图合计约 700px。两个独立滚动区（滚趋势图时事件不跟着走）。
6. **维度标题去掉"维度 N/6"编号**（用户："这些都不要了，多余"）——维度名本身够认，
   编号既不用来引用也不用来排序。连带把全局提示里"维度3/维度4"的说法改成维度名，
   否则界面上没编号了、那句话对不上。

「复制全文」按钮从窗口底部挪到通栏标题行，底部整行取消（省约 40px 给数据）；
「关闭」按钮一并去掉——窗口右上角的 X 和 Esc 都还在。导出内容现在**带上六个维度的结论**
（只导结论和告警、不导证据表：贴进分析笔记的是判断，几十行区间对照数字贴过去没人会再读，
要查证据回窗口看）。

## 10. 原型脚本

原型脚本（只读库、不写任何东西）已按本方案第 4 节全部六个维度实跑宁德时代，
输出见会话记录。它的作用是**在写产品代码前验证口径**，已经因此改掉三处：

1. 分档资金流起始日不能用全表 `MIN`（虚报 4 个月）
2. 大宗溢价率必须金额加权（简单平均 -1.13% vs 加权 -0.05%，结论方向不同）
3. 占比显示不得四舍五入进位（99.7% 会显示成 100%，与折价 0.3% 相加超过 100%）

原型脚本是**一次性的**，不入库、不留在 publish 或项目根（诊断脚本一律只写 scratchpad）。
它的输出基准已经抄在本节上方和第 1 节，产品代码的对数测试（`CapitalDiagnosisTests.对数_宁德时代`）
就是拿这些数字当断言，所以脚本本身丢了也无妨。

v3 相对 v2 的唯一变化是**补上每个维度的结论句**——v2 只有表格，六个维度铺开后看不出是"六个维度的分析"，
跟现有档案窗口的原始表没有区别。这条是本功能成立与否的关键：**没有结论句就没有第三层。**
