# 离线模拟数据源（Offline Mock）

只在 **DEBUG 构建**里存在的一套假数据源：打开之后整条抓取链照常跑——排期、四道闸、落库、
待办、复查、UI 链一个环节都不少——只有"把请求发出去"那一层换成了本地构造。

> 这份文档是这套设施的说明书。散在各设计文档里的那些"这一轮走离线模拟"都指向这里：
> `doc/retry-backlog-design.md`（`MockBarFetcher` 的来历）、`doc/margin-task-design.md` §9、
> `doc/day-completeness-check-design.md`。

## 1. 为什么要它

**① 单测覆盖不到的那一半。** 纯函数都能测，但"界面点下去之后整条链对不对"测不了——
调用环路、事件桥接、分派顺序、manifest 落账，这些只有真跑一遍才知道
（2026-09-08 的教训：单测测不出调用环路和 UI 链，见 `feedback_verify_by_running_app`）。

**② 真跑一轮太贵。** 【重新拉取失败】那条链跑一轮是几千个请求、几个小时；
股东数据一轮 11,130 个新浪请求；整段回补两融是 4,288 个交易日。
验一次编排逻辑不值当付这个代价。

**③ 会跟正式实例抢配额。** 本机在抓数据时，Debug 实例再去打同一个源，
轻则互相限流，重则把正式那轮的数据抓漏（见 `feedback_no_local_network_probing`）。

**④ 源本身可能不让抓。** 2026-09-18 上午新浪整域 456，真跑根本跑不起来。

## 2. 两个开关

都写在 `data/fetcher-settings.json`（JSONC，每个可选值在模板里都有一行去掉 `//` 就能用的完整配置）。

| 开关 | 管什么 | 起于 |
|---|---|---|
| `"BarSource": "Mock"` | K线 + 股票名册 | 2026-09-13 |
| `"OfflineMock": "true"` | 其余所有**已有模拟源**的数据源 | 2026-09-18 |

**为什么其余是一个总开关、而不是每类一个**：逐类去配必然漏。2026-09-18 验
【拉取区间数据】时就是每类配的，漏了资金净流入和龙虎榜，当场发出真请求。
验证要的是"这一轮一个真请求都不发"，那就只能有一个开关。

K线单独留在 `BarSource` 里，是因为那一项本来就是"选哪个数据源"的语义
（`Tencent` / `Sina` / `EastMoney` / `Mock` 并列），不是"要不要模拟"。

## 3. 现有的模拟源

都在 `src/StockPlatform.Data/Remote/Mock*.cs`。

| 类 | 顶替 | 造出来的数据 |
|---|---|---|
| `MockBarFetcher` | 所有K线源 | 区间里每个工作日一根，OHLC 全是 `11.11`，量额换手给非零常数，抓取时刻记成当天 20:00 |
| `MockStockListProvider` | 股票名册 | **直接读本地库已有的名册**，不造假代码（造了的话每一轮抓取都会跟着跑它们） |
| `MockMarginProvider` | 交易所两融 | 每个工作日 10 行，沪深各一半，余额 `111111` 起 |
| `MockNetInflowFetcher` | 新浪资金净流入 | 区间里每个工作日 1 行，净流入 `1111111` |
| `MockLhbProvider` | 东财/新浪龙虎榜 | 每个交易日 4 行，沪深各一半 |
| `MockShareholderProvider` | 新浪股东数据 | 见其类注释 |
| `MockLhbSeatProvider` | 东财龙虎榜席位（按日） | 每个交易日买卖各 5 个席位，沪深各一半 |
| `MockBlockTradeProvider` | 东财大宗交易（按日） | 每个交易日 6 行，沪深各一半，成交额 `1111111` 起 |
| `MockIndexConsProvider` | 新浪指数成分 | 每个指数 5 只成分，沪深各一半；`EmptyFor` 里的返回空（＝真源上"这个指数没有成分"） |
| `MockIndexWeightProvider` | 中证指数权重 | 每个指数 5 行，基准日＝上月末；默认"代码不以 0 开头的都没有文件"（模拟 404） |
| `MockMarketCapFetcher` | 新浪流通市值 | 一次扫回全市场（含 2 只"新股"），市值 `1111111111`；默认 `QuotesAreLive=false`＝盘后档 |

三条**故意的**约定，改之前先读懂：

- **一眼可辨的假值**（`11.11` / `111111` / `1111111`）：混进真库时查得出来。
- **当天返回 0 行**（两融、龙虎榜）：模拟 T+1 / 当晚发布。不这样的话
  "今天的空不该定案"那条判据（`DailyNoDataGate`）根本验不到。
- **模拟源要模拟"正常的空"**，不只是"有数据"：指数成分的 `EmptyFor`（某些老指数本就没有成分）、
  权重的 404（非中证系没有权重文件）、市值的 `QuotesAreLive=false`（盘后档）——
  这三条各自对应一条"空不算失败 / 空要记进另一份名单 / 日期要归到上一个交易日"的判据，
  模拟源不还原它们，那些判据就验不到。
- **沪深各一半**：日频体检有"某个交易所整天没有"的判据，只造一个市场会被报成残缺日，
  那就不是在测要测的东西了。
- `MockBarFetcher` 的 `FailMarker = "999"`：代码里含 `999` 的一律抛异常，用来验失败名单那条路。
  所以日志里 `sz159998 按约定抓取失败` 是**预期行为**，不是真失败。
- `MockLhbProvider` **故意不实现 `ILhbRangeProvider`**：实现了 `LhbTask` 就会走按月切片，
  而【拉取区间数据】和补残缺日走的都是逐日路径——要模拟的正是后者。
- 席位和大宗的 **`Reported*` 必须跟实际造的行数对上**：这两张表是整日替换，
  `IsComplete` 对不上就整天不落库。随手写个不一致的 count，模拟源一开每天都成"残缺日"，
  测的就不是要测的东西了。要模拟限流截断，用它们的 `ShortBuy`/`ShortSell`/`Short`——
  那几个属性的做法正是"count 照报全数、行少给一条"。
- 席位和大宗**只换按日抓那一路**：`EastMoneyMarketEventProvider` 还要给机构调研/股东增减持/
  限售解禁用，那几路没有模拟源，整体替换会把它们打掉。

## 4. 两道安全闸——都别拆

**① 只在 DEBUG 构建里注册。** Release 的数据源下拉里没有 `Mock`，`OfflineMock` 那段代码
连编译都不参与（`#if DEBUG`）。

**② Debug 实例的数据目录天然隔离**：`bin\Debug\...\win-x64\data`，跟正式实例的 `publish\data`
不是同一个库。

它写进库的是**假数据**，误开一次就得清库。两道闸是独立的，缺一道都不够。

## 5. 怎么用

```jsonc
// Debug 的 data/fetcher-settings.json，验完记得撤掉
{
  "OfflineMock": "true",
  "BarSource": "Mock",
}
```

然后起 Debug 实例跑。**开跑之前这三件事别省**：

1. **先清干净待办**。【重新拉取失败】会把 manifest 里所有欠账挨个跑一遍——
   其中没有模拟源的那些（席位、大宗…）会真发请求。2026-09-18 就这么漏发过 2 个。
2. **每次点按钮前重新枚举行号**。计划表的行序会随依赖和状态变化——照上一轮记住的行号点，
   会点到别的项上（那次点成了【指数日K】，发出 9 个真请求）。
3. **确认本机没在抓数据**（`Get-Process *StockPlatform*`）。

验完收尾：撤掉那两个开关、清掉写进 Debug 库的假数据、关掉实例。

**实测**（2026-09-18）：manifest 里同时挂着席位/大宗/龙虎榜/两融四项残缺日，点一次
【重新拉取失败】——四项全部补上、总耗时 0 秒、**一个真请求都没发**，待办复查后清空、
"确认没有"名单没有误加。同一个场景在补这两个模拟源之前会漏发真请求。

⚠ 【拉取区间数据】还需要本地名册里**有股票**（`StockMeta` 里 `type='stock'` 的行）——
`MockStockListProvider` 读的就是它，空的话整项会直接失败退出。

## 6. 还没有模拟源的（这些仍会真发请求）

市场事件里除大宗以外的三路（机构调研、股东增减持、限售解禁）、板块与成分股、中标公告、
财务报表、行业分类、分红送配、ETF 名单、退市名单、交易日历、业绩预告/快报、
分档资金流（push2his）、总股本、公司档案、客户与供应商……

所以**"打开开关 ≠ 整个程序离线"**。跑【拉取全部】或整组时，上面这些照样会联网。
只有当这一轮涉及的源都在 §3 表里，才能说"零请求"。

中标公告有个便宜的绕法：把那一行的「关键词」格清空，那一段就整段跳过。

## 7. 加一个新的模拟源

1. 在 `Data/Remote/` 写 `MockXxx.cs`，实现对应接口；照 §3 的三条约定
   （可辨的假值、必要时当天返回 0 行、沪深都要有）。
2. `App.xaml.cs` 里把那个 provider 的构造改成三元：`offlineMock ? new MockXxx() : 原来的`。
   **挂到已有的 `offlineMock` 总开关上**，不要再加一个自己的开关键（理由见 §2）。
3. 更新本文 §3 的表和 §6 的清单，以及 `FetcherSettings` 模板里 `OfflineMock` 那段的说明。
