## 1. 查出来的两个问题

### 1.1 三个字段数据源一直在返回，我们没解析

实测 2026-09-14 的真实响应：

**上交所** `query.sse.com.cn/.../queryMargin.do`（JSON）实际返回

```json
{"stockCode":"510050","securityAbbr":"50ETF",
 "rzye":1481494528,      // 融资余额     ✓ 已取
 "rzmre":88951106,       // 融资买入额   ✓ 已取
 "rzche":59724213,       // 融资偿还额   ✗ 没取
 "rqyl":36564540,        // 融券余量     ✓ 已取
 "rqmcl":1415000,        // 融券卖出量   ✗ 没取

```

**深交所** `szse.cn/api/report/ShowReport`（xlsx）共 8 列，原先只读 0,1,2,3,5,6：

| 列 | 含义 | 原先 |
|---|---|---|
| 0 / 1 | 代码 / 简称 | ✓ |
| 2 / 3 | 融资买入额 / 融资余额 | ✓ |

跟东财 `columns=ALL` 那次是同一个毛病（project_em_columns_all_dropped）：**缺字段是解析丢的，不是没取到，加字段零新增请求。**

### 1.2 沪市融券余额恒为 0 —— 静默失效了很久

上交所的 `rqylje` **恒为 null**，而解析用的 `GetNum` 把 null 读成 0：

```
沪市 MarginDetail 行数            3,139,554
其中 short_balance > 0 的行数             0     ← 历史上从来没有过非 0 值
深市 short_balance > 0 的行数     （当日 2430 只里 69% 有值，合计 106.5 亿）
```

后果是静默的：资金面诊断的「融券余额变化」对**所有沪市票**算不出来，而界面上显示的是
"融券余额 0"——看起来像"这只票没人做空"。宁德时代是创业板（深市），所以做那个功能时没暴露。

**教训**：凡是源头可能不给的列，模型里就得可空。把"没有"写成 0，下游永远分不清
"这个市场不提供"和"当天确实是 0"。

## 2. 融券余额怎么补出来

公式是**交易所自己写的**。深交所报表页脚原文：

> 本日融资余额(元) = 前日融资余额 ＋ 本日融资买入 − 本日融资偿还额
> 本日融券余额(元) = **本日融券余量 × 本日收盘价**
> 本日融资融券余额(元) = 本日融资余额 ＋ 本日融券余额

沪市不给余额但给了余量，收盘价本地有 → 按同一公式补，跟深市完全同口径。

**实测验证**（2026-09-14）：

| 对照 | 样本 | 误差中位 | 90 分位 | 最大 |
|---|---|---|---|---|
| 深市（对交易所自己给的余额） | 1,603 只 | 0.0000% | 0.0000% | 0.709% |
| 沪市（对东财公布值） | 456 只 | 0.0000% | 0.0000% | 3.235% |

沪市那一版全部用**库里的数据**算（交易所给的余量 × 我们自己的收盘价），逐只对照东财：

| 代码 | 名称 | 库里余量 | 库里收盘 | 算出 | 东财公布 | 误差 |
|---|---|---|---|---|---|---|
| 600036 | 招商银行 | 9,771,516 | 41.83 | 408,742,514 | 408,742,514 | 0.000% |
| 601318 | 中国平安 | 5,374,850 | 54.73 | 294,165,540 | 294,165,540 | 0.000% |
| 600519 | 贵州茅台 | 127,848 | 1277.96 | 163,384,630 | 163,384,630 | 0.000% |

顺带确认**两个源的原始数据完全一致**：沪市 500 只票的融资余额逐一对照东财，
误差中位 0.000000%、最大 0.000000%、完全相同的占 100.0%。

## 3. 融资净买入：两种口径，结果等价

**净买入 = 买入额 − 偿还额。** 两条路都能算：

- **沪市**：源头给了 `rzche`，直接减
- **深市**：源头不给，用**融资余额的日变动**。依据就是上面那条页脚恒等式——
  余额差分 ≡ 买入 − 偿还

**实测同源验证**（贵州茅台，东财数据，余额差分 vs 官方公布的净买入）：

| 日期 | 余额差分 | 官方净买入 | 差 |
|---|---|---|---|
| 09-07 | 19,865,787 | 19,865,788 | −1 |
| 09-08 | 36,604,529 | 36,604,529 | 0 |
| 09-09 | 164,338,774 | 164,338,773 | +1 |
| 09-10 | −35,275,006 | −35,275,005 | −1 |
| 09-11 | −34,104,702 | −34,104,703 | +1 |
| 09-14 | −33,545,806 | −33,545,807 | +1 |
| **09-15** | −51,023,479 | −51,843,258 | **+819,779** |

±1 元是四舍五入。**只有最新一天对不上**——那天数据还没定稿（兆易创新同日差 580 万）。
跟「盘中K线不是最终值」是同一类问题（project_intraday_bar_confirmation）。

**所以不去抓偿还额的历史**：差分法已经等价、覆盖 2010-03-31 至今全历史，而抓偿还额
只能从今往后攒（两所都不提供历史查询，只能按交易日逐日抓）。新增的 `margin_repay` 列
老行一律 NULL，不回填。

### 3.1 买入额会骗人，必须和净买入并列

买入额是**总流水**（买了又还、还了又买都计在内）。宁德时代实测：

| 日期 | 融资买入额 | 净买入 | 当日涨跌 |
|---|---|---|---|
| 2026-08-06 | 17.0 亿 | **+7.45 亿** | −4.26% |
| 2026-09-08 | 15.9 亿 | **+2.53 亿** | −3.65% |
| 2026-08-27 | 11.1 亿 | **+6.00 亿** | −1.58% |

区间买入额合计 **231 亿**，净买入只有 **+12.25 亿**（19 倍差）。
9/8 买入额排区间第二，看着像大举抄底，实际净买入只有 2.53 亿——那天是**大进大出**。

所以维度4 的 Top3 表改成 `日期 | 融资买入 | 净买入 | 当日涨跌`、按净买入排序。
只给买入额会读成"猛加仓"，只给净买入又看不出流水规模，**两个必须并列**。

### 4.1 补算器的四个要点

1. **只动沪市**。深市有 31% 的行 `short_balance = 0`，那是**真的 0**（当天确实没融券余量）。
   判据不能只看"是不是 0"，必须先分市场。
2. **市场判断走 `MarketClassifier`，ETF 走库里存的前缀**。`MarketClassifier` 的职责是
   "从 6 位**股票**代码判板块"，ETF 的 5xxxx 它返回 `Unknown`。而 ETF 的市场前缀在这个项目里
   **从来不是算出来的**——是新浪 ETF 列表接口直接给的 8 位符号（`sh510300`），原样存进
   `Bar`/`StockMeta`。所以 ETF 查这两张表里存的是 `sh` 还是 `sz`，**不另造"5 开头算上交所"的规则**
   （自写前缀规则的代价见 feedback_market_prefix_via_classifier）。
3. **ETF 找收盘价要试带前缀的代码**。两融表里是裸码 `510050`，`Bar` 里是 `sh510050`。
   只按裸码找会让 323 只本来有数据的 ETF 也算成"补不上"。
4. **按交易日分批提交**（沪市每天约 1700 行）。单事务写几百万行曾把 WAL 撑到 162 GB
   （project_wal_blowup_and_stale_dotnet）。分批还顺带解决了断点续——补过的行不再满足
   缺值判据，中断直接重跑。

### 4.2 回填规模

```
沪市有融券余量的行  2,697,619
能配到当日收盘价    2,631,346  (97.54%)   ← 会被补上
配不上               66,273  (2.46%)     ← 留 NULL
```

补不上的 2.46% **不是缺陷**：478 个两融标的在库里一根日 K 都没有，构成是
**465 只 ETF** + 12 只历史退市/更名股票 + **1 只仍在交易的股票**。

⚠ 最后那只是 **689009 九号公司**（科创板 CDR，两融数据到 2026-09-14 仍在更新），
它不在 `StockMeta` 里、一根 K 线都没有，所以选股/诊断/所有基于 K 线的分析都看不到它。
另有 465 只 ETF 缺 K 线（科创板 588/589 那批缺 77 只），说明 ETF 名单覆盖不全。
**这两个是独立问题，不在本次范围内。**
