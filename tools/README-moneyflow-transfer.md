# 分档资金流「搬运」——在别的机器上抓历史，拷回来导入

## 为什么要搬

分档资金流（超大单/大单/中单/小单各自的净额与净占比）的**历史**只有一个来源：
`push2his.eastmoney.com` 的 `fflow/daykline`，一次给最近约 120 个交易日。

2026-09-11 起这台机器所在的公司网把 `push2his` **整个域名**拦了：TCP 和 TLS 都握手成功，
一发 HTTP 请求就被切断、收到 0 字节。有线和 Wi-Fi 走的是同一个网关、同一个出口公网 IP
（实测都是 74.211.106.166），所以换网卡没用，`Push2NetworkInterface` 这个设置也救不了。

当天数据不受影响——那条走 `push2delay` 的全市场快照一直是通的，日常增量照跑。
**只有补历史这段需要搬。**

替代方案都试过、都不行：`push2delay` 的 `fflow/daykline` 通，但只返回当天一行；
`push2` 的 `fflow/daykline` 被切（尽管同域的 `clist` 通）。

## 三步

### ① 本机：导出待抓清单

```
dotnet run --project tools\MoneyFlowTransfer -- export-codes --date 2026-09-09 --split 6
```

写出 `publish\moneyflow-transfer\part1..part6\`，每个目录里是 `codes.txt` + 抓取脚本 + 用法说明，
拷一个目录到一台机器就能开跑。

三种选清单的方式：

| 参数 | 选出来的是 |
|---|---|
| `--date 2026-09-09` | **那天有日K、但缺分档资金流的票**（最准） |
| 不带参数 | 窗口内缺行的票（判据跟程序里那一项共用 `MoneyFlowBackfillPlan`） |
| `--all` | 全部个股名册 |

`--date` 那条判据是实测立住的：库里「那天有资金流却没有日K」的票是 **0 只**，所以没开盘交易
（停牌/未上市）就不会有资金流，问了也是空。09-09 那天全市场 5561 只个股里有 13 只是这样，
按日期筛能自动把它们剔掉，不白发请求。

`--split N` 是**轮流发牌**不是切段：代码是排好序的，切段会让某一份全是 60xxxx、另一份全是
000xxx，万一某个市场段整体出问题（限流、secid 规则变了），受影响的是一整份而不是均摊。
每份清单头部写着 `# part: n/N`，抓取脚本认这一行，把 CSV 命名成 `moneyflow-<日期>-p<n>.csv`
——六台机器的产物拷到一处不会互相覆盖。

> ⚠ secid 在这一步算好，外机脚本不自己猜。北交所 920xxx 要用 `0.` 前缀，
> 猜成 `1.` 的话东财返回空、不报错——2026-09-06 那 342 只就是这么静默丢了两天。

### ② 外机：抓成 CSV

把 `moneyflow-part<N>.zip` 拷到一台能访问 `push2his` 的机器上，解压到一个**固定目录**
（别在 zip 里直接双击运行——那是 Windows 临时目录，关掉窗口数据就没了）。
包里有两个版本，抓法、节奏、CSV 格式完全一样，看手边是什么机器挑一个：

**A. `moneyflow-fetch.ps1`（Windows）**

```
powershell -ExecutionPolicy Bypass -File .\moneyflow-fetch.ps1
```

产出在 `out\`：`moneyflow-<日期>-p<份号>.csv`（数据本体）、`done.txt`（断点续跑索引）、
`failed.txt`、`fetch-log.txt`。

**B. `moneyflow-fetch.html`（任何系统，Mac 也能用）**

浏览器打开它 → 选 `codes.txt` → 点「开始」。抓到的数据存在**浏览器本地库**里，
关页面不丢，回来点「开始」自动从没抓过的那只往下走。抓够了点「下载 CSV」拿走文件，
确认导入成功后再点「清空本机数据」。

- 为什么浏览器里能抓东财：这些接口支持 JSONP（`cb=` 参数），用 `<script>` 标签取数，
  完全绕开跨域；实测**不带 Referer 也放行**，所以页面声明了 `no-referrer`。
- 为什么不用 `localStorage`：它只有 5~10MB，而一份 850 只约 13MB，写到一半就爆——
  而那时候已经烧掉几百个请求了。所以用 IndexedDB。
- ⚠ **Safari 在 `file://` 下不给用 IndexedDB**。Mac 上要么用 Chrome，要么在那个目录里起
  个本地服务（Mac 自带 python3）：`python3 -m http.server 8000`，再开
  `http://localhost:8000/moneyflow-fetch.html`。页面打不开数据库时会把这两条办法打在日志里。

**两个版本共同的节奏**（默认值照实测的限流边界定的，一般不用动）：每抓 10~15 只歇 2~5 分钟，
批量和歇多久**都是随机的**，请求间隔另带 ±30% 抖动。东财的触发点是**累计请求数**不是速率，
光降速没用；而「每 15 个整、歇整 2 分钟」这种精确周期本身就是机器行为最好认的特征。

**换网络解决不了限流**：`push2his` 实测累计 16~35 个请求就被切，这是服务端按出口 IP 算的配额。
所以这活是"跑多少算多少"——抓到的一律保留，关窗口、断网、连续失败自动收尾，
已抓的部分都在，下次接着来。带着笔记本换个 WiFi 就是一个新出口。
### ③ 本机：导入

```
dotnet run --project tools\MoneyFlowTransfer -- import <拷回来的csv> [更多csv...]
```

支持通配，六份一条命令全导：`import 收回来的目录\moneyflow-*.csv`。走的是产品代码里那个
`SqliteNetInflowDetailRepository.Upsert`（INSERT OR REPLACE），所以：

- **重复导入安全**，同一份 CSV 导两遍结果一样；
- 跟程序自己抓的数据完全同构，`fetched_at` 用的是外机实际抓取的时刻；
- 导入前会**逐字校验表头**——净额和净占比全是数字，列串了谁也看不出来，只有回测结果会
  莫名其妙，所以宁可拒绝导入；
- `--dry-run` 只解析和校验、不写库。

导入完会报「导入前/导入后」的只数与行数。净增数小于 CSV 行数是正常的：已有的那些行被覆盖了。

## 已知边界

- 接口只给最近约 120 个交易日，**更早的补不回来**。缺口拖久了就永久没了，值得早点搬一次。
- 外机抓的是它跑的那天的 120 天窗口。窗口天天往前滚，所以搬一次只能填到那天为止，
  后面靠本机的日常快照接上。
- 导出清单那步会读 25GB 的库并算缺口（实测 5 秒）。抓取程序正在写库时也能跑，
  但要是撞上长事务可能等一会儿。
